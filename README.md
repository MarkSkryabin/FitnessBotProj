# Fitness Assistant Bot

**Telegram-бот для учёта воды, питания и тренировок с персональным дневным прогрессом.**

Бот помогает вести профиль пользователя, записывать выпитую воду, учитывать калорийность продуктов и расход энергии на тренировках. Данные сохраняются в SQLite, взаимодействие с Telegram реализовано через aiogram 3.

Дневная цель по воде рассчитывается с учётом веса, активности и текущей температуры в городе пользователя. Цель по калориям можно рассчитать автоматически или указать вручную.

## Возможности

- Пошаговая настройка профиля: вес, рост, пол, возраст, время активности и город.
- Автоматический расчёт целей по воде и калориям.
- Учёт воды в миллилитрах.
- Поиск калорийности продукта через Open Food Facts и расчёт по массе порции.
- Учёт шести типов тренировок и дополнительной воды после нагрузки.
- Просмотр дневного прогресса с текстовыми индикаторами, потреблёнными и потраченными калориями.
- Подсказки продуктов из встроенного списка с учётом оставшихся калорий.
- Хранение профилей и текущих дневных показателей в SQLite.

## Технологии

| Назначение | Инструменты |
| --- | --- |
| Telegram и диалоговые состояния | aiogram 3, FSM |
| Асинхронные HTTP-запросы | HTTPX |

## Установка и запуск

### 1. Склонируйте проект

```bash
git clone https://github.com/MarkSkryabin/FitnessBotProj.git
cd FitnessBotProj
python -m venv .venv
```

Активация в Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Активация в Linux / macOS:

```bash
source .venv/bin/activate
```

В качестве отправной точки для окружения можно использовать Python 3.11. Проверьте установку зависимостей в своей среде.

### 2. Установите зависимости

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### 3. Настройте токены

Получите токен Telegram-бота через [BotFather](https://t.me/BotFather) и API-ключ для погоды в [OpenWeatherMap](https://openweathermap.org/).

Создайте или обновите `.env` в корне проекта:

```dotenv
BOT_TOKEN=your_telegram_bot_token
API_TOKEN_WEATHER=your_openweathermap_api_key
```

Обе переменные обязательны: `config.py` завершает запуск с ошибкой, если любая из них отсутствует. Для поиска продуктов отдельный API-ключ в текущем коде не используется.

Используйте собственные токены. Храните `.env` вне публикуемых файлов проекта.

### 4. Запустите бота

```bash
python bot.py
```

При запуске вызывается `init_db()`, которая создаёт таблицу `users`, если её ещё нет. Затем бот начинает получать обновления через **long polling**. Отдельный HTTP-сервер для этого режима не нужен.

Запускайте команду из корня проекта: `fitness_database.db` открывается по относительному пути. Репозиторий уже содержит файл базы; для отдельной установки можно изменить `DB_PATH` в `db.py` на имя новой базы.

Для работы требуется доступ к Telegram, OpenWeatherMap и Open Food Facts. При размещении на сервере сохраняйте файл SQLite на постоянном диске.

## Команды

| Команда | Назначение |
| --- | --- |
| `/start` | Приветствие и начало работы |
| `/help` | Список команд |
| `/set_profile` | Создание или обновление профиля |
| `/profile` | Просмотр параметров и дневных целей |
| `/log_water <мл>` | Запись выпитой воды |
| `/log_food <продукт>` | Поиск продукта и последующий ввод массы в граммах |
| `/log_workout <тип> <мин>` | Запись тренировки |
| `/check_progress` | Дневной прогресс и баланс калорий |

### Пример использования

1. Отправьте `/start`, затем `/set_profile` и заполните параметры по подсказкам.
2. Для автоматической цели по калориям ответьте `да` в нижнем регистре; для ручной — отправьте число.
3. Записывайте воду, продукты и активность:

   ```text
   /log_water 250
   /log_food яблоко
   /log_workout бег 30
   /check_progress
   ```

После `/log_food` бот показывает найденный продукт и калорийность на 100 г, затем ожидает массу порции отдельным сообщением, например `150`.

## Расчёты в текущем коде

### Вода

Базовая дневная цель, в миллилитрах:

```text
30 × вес_кг + 500 × floor(активность_мин / 30)
```

Если текущая температура выше 25 °C, добавляется:

```text
15 × (температура − 25)²
```

При записи отдельной тренировки цель дополнительно увеличивается на `200 × floor(длительность_мин / 30)` мл.

### Калории и тренировки

Автоматическая цель в `day_value_calorie()` зависит от веса, роста, возраста, пола и времени активности. Это собственная формула проекта; вручную заданная цель используется напрямую.

Расход энергии на тренировке вычисляется по фиксированным коэффициентам:

| Тип для команды | Ккал в минуту |
| --- | --- |
| `бег` | 10 |
| `ходьба` | 5 |
| `велосипед` | 8 |
| `плавание` | 11 |
| `силовая` | 9 |
| `йога` | 4 |

В `/check_progress` баланс равен потреблённым калориям за вычетом потраченных. При этом индикатор достижения цели и остаток калорий рассчитываются по потреблению, без вычета тренировок.

## Хранение данных

В таблице `users` хранится одна запись на Telegram ID: параметры профиля, дневные цели, выпитая вода, потреблённые и потраченные калории, дата последнего обновления.

Отдельного журнала приёмов пищи, тренировок и прошлых дней в текущей схеме нет. Проверка смены дня выполняется при обращении к обработчикам бота и использует локальную дату сервера.

## Особенности текущей реализации

- **Смена дня требует исправления:** в `db.py`, внутри `new_day()`, асинхронная `day_value_water()` вызывается без `await`. Перед использованием дневного сброса замените вызов на `new_water_goal = await day_value_water(weight, activity_time, city)`. Иначе в запрос SQLite передаётся объект coroutine, и обновление завершается ошибкой.
- FSM хранится в памяти стандартного `Dispatcher()`: незавершённый диалог после перезапуска не восстанавливается, а сохранённые профили остаются в SQLite.
- Поиск продукта использует первый результат Open Food Facts. Перед вводом массы проверьте название и калорийность, показанные ботом.
- Ввод `Да` проходит одну проверку обработчика, но не совпадает с условием `text == 'да'` в функции расчёта. Для автоматической цели используйте `да` либо нормализуйте ввод в коде.
- Middleware печатает текст входящих сообщений в консоль; это следует учитывать при хранении серверных логов.
